# Система анимаций карт

Дата: 2026-08-26

## Задача

Все перемещения карт за столом должны быть непрерывными и прерываемыми. Ни
одна карта не должна появляться или исчезать рывком, ни одна панель не должна
скачкообразно менять высоту.

Наблюдаемые дефекты, с которых началась работа:

1. Карта вето остаётся лежать на столе и резко исчезает вместо полёта в сброс.
   То же с перенаправлением.
2. Добор карты в руку — резкий.
3. Hover карты в руке дёргается при быстром движении курсора.
4. Возврат карты с кона в руку выглядит как два независимых события: карта
   гаснет на столе, затем отдельно проявляется в руке.
5. При проверке карты игрока вторая карта в руке может исчезнуть.
6. Панель действий скачком меняет размер при смене фазы.

## Диагноз

Дефекты — следствия архитектуры, а не настроек CSS.

**У карт нет идентичности.** `Player.hand` — это `GameCard[]`, массив строк с
названиями. Слоты руки восстанавливаются эвристикой сопоставления по имени в
`apps/web/src/lib/handSlots.ts`, а карта «на кону» прячется по индексу
`pendingAction.stakedCardIndex`.

**Отсюда дефект 5.** В `packages/engine/src/resolvers/doubtResolver.ts` при
вскрытии выполняется `actorHand.splice(stakedIndex, 1)` — карта уходит из руки
немедленно, а `pendingAction.stakedCardIndex` продолжает указывать на тот же
индекс. Рука стала короче, и `isCardStaked` начинает прятать соседнюю карту.

**Полёты карт не долетают.** `@keyframes fly-discard` смещает карту на `34vw`
вправо и гасит до нуля. Реальная позиция назначения нигде не измеряется, и
самого сброса в интерфейсе не существует — только счётчик в кодексе.

**Тайминг размазан по четырём независимым константам.** `visualEffects.ts`
ставит `setTimeout(850)`, CSS-анимации длятся 750–800 мс, `--dur-move` равен
280 мс, `HAND_EXIT_MS` — тоже 280. Их приходится синхронизировать вручную.
Если `pendingAction` очищается посреди полёта, карта размонтируется на
середине траектории — это дефекты 1 и 4.

**Монтирование карт стола управляется клубком булевых флагов.**
`StakedCardArena.tsx` (330 строк) выводит видимость из `showPile`,
`hasCardDeparted`, `isSingleFlight`, `cardAlreadyResolved` и
`isPendingActionAfterTruthChallenge`. Комментарии в файле — история заплаток по
одному дефекту за раз.

## Решение

### 1. Идентичность карт в движке

```ts
export type CardId = string;                    // 'c17'
export interface CardInstance { id: CardId; card: GameCard }
```

`deck`, `discardPile` и `Player.hand` становятся `CardInstance[]`. ID выдаются
один раз при сборке колоды (`c0`…`c59`) и живут до конца партии; перетасовка
сброса обратно в колоду их сохраняет.

`Action.stakedCardIndex` заменяется на `stakedCardId`, `stakedCardIndices` — на
`stakedCardIds`. `ActivePlotData` получает поле `cardId`.

Редакция состояния для онлайна публикует `{ id, card: GameCard | null }`: ID
виден всем, лицо чужой карты скрыто. Сброс публикуется целиком — по правилам
это открытое «Кладбище двора». У колоды публикуется только размер, поэтому
карта с ранее неизвестным ID, появившаяся в руке, однозначно трактуется как
пришедшая из колоды рубашкой вверх.

Чтобы места чтения не распухли, добавляются хелперы `faces(hand)`,
`idOf(hand, card)` и `holds(player, card)`.

Это устраняет дефект 5 в корне: `isCardStaked` сравнивает ID, и после
`splice` в doubtResolver прятать соседнюю карту нечем — искомого ID в руке
больше нет.

### 2. Зона как производная от состояния

Чистая функция `deriveCardZones(state, viewerId)` строит из текущего состояния
`Map<CardId, Zone>`; хук `useCardZones()` — тонкая обёртка над ней:

```ts
type Zone =
  | { kind: 'deck' }
  | { kind: 'hand'; playerId: string; slot: 0 | 1 }
  | { kind: 'stake' }
  | { kind: 'duel'; side: 'attacker' | 'defender' }
  | { kind: 'table' }
  | { kind: 'overlay' }
  | { kind: 'plot'; playerId: string }
  | { kind: 'discard' };
```

Параллельно строится `Map<CardId, Face>` — известно ли лицо карты (из
`revealOutcome`, `duelOutcome` или потому что это рука зрителя) или показывается
рубашка.

Из движка удаляются `cardFlightEvent`, `hasCardDeparted`,
`cardAlreadyResolved`, визуальное применение
`isPendingActionAfterTruthChallenge` и все таймауты полётов в
`visualEffects.ts`. Движок перестаёт знать об анимациях. Забыть анимировать
перемещение становится невозможно: перемещение вытекает из данных.

### 3. Единый слой карт, якоря в вёрстке

Карта — единственный DOM-узел, который не размонтируется при смене зоны.

Рука, стол, места оппонентов, слот интриги и угловые точки рендерят пустые
якоря `<CardAnchor zone={…}>`. Якоря держат раскладку и задают размер. Все
карты рендерятся в одном `position: fixed` слое `<CardLayer>` поверх стола — по
одному `motion.div` на `CardId`. Хореограф читает `getBoundingClientRect()`
якоря и ведёт карту к нему пружиной по `x`, `y`, `width`, `height`, `rotate`.
Сменился якорь — карта туда полетела.

Прямые следствия:

- Карта вето и перенаправления не исчезают: узел жив, у него сменилась зона на
  `discard`, он туда долетает (дефект 1).
- Возврат с кона в руку — одно непрерывное движение одного узла (дефект 4).
- Размер интерполируется между якорями, скачков нет (рука → стол → мини-слот
  оппонента) (дефект 6 в части карт).
- Прерываемость бесплатна: пружина перецеливается с текущей скоростью, если
  состояние сменилось на полпути.

Цена: hover, клик и подсказки переезжают с `Card`, `FaceCard` и `FlipCard` на
карточку в слое, которая выводит свои affordance из зоны. Переворот остаётся
дочерним элементом внутри узла, поэтому 3D-трансформация не конфликтует с
позиционированием.

Якоря рендерят раскладку и размер, но не рендерят карту, поэтому пустой слот
руки не схлопывается, когда карта ушла на кон.

### 4. Угловые якоря вместо стопок

Видимых колоды и сброса на столе нет — места мало. Левый верхний угол стола
служит якорем источника (откуда приходят карты), правый верхний — якорем
сброса. Это невидимые точки: карта на подлёте к углу уменьшается и гаснет,
из угла — наоборот.

### 5. Токены движения

Один файл `apps/web/src/motion/tokens.ts`:

```ts
export const spring = {
  flight: { stiffness: 260, damping: 30, mass: 1.0 },
  settle: { stiffness: 420, damping: 34, mass: 0.7 },
  hover:  { stiffness: 520, damping: 32, mass: 0.5 },
  press:  { stiffness: 700, damping: 30, mass: 0.4 }
};
export const dur = { flip: 0.5, fade: 0.18, panel: 0.26, stagger: 0.06 };
```

Те же значения экспортируются в CSS-переменные для того, что остаётся на CSS.
Четыре рассинхронённые константы заменяются одним источником.

### 6. Каталог движений

Все перечисленные переходы вытекают из разделов 2 и 3 автоматически; под каждый
подбирается пружина и сдвиг, отдельная анимация не пишется.

| Событие | Движение |
| --- | --- |
| Добор в руку | из левого угла рубашкой вверх, дуга к слоту, мягкий overshoot, переворот лицом в конце; две карты со сдвигом 60 мс |
| Карта на кон | из слота руки в центр стола, слот остаётся пустым |
| Никто не усомнился | с кона обратно в свой слот одним движением |
| «Не верю» | переворот лицом на месте, пауза, полёт в угол сброса |
| Вето | карта вето вылетает из руки, ложится поверх кона с наклоном, затем обе уходят в сброс со сдвигом |
| Перенаправление | ложится поверх кона, затем в сброс |
| Дуэль | две карты сходятся из своих рук, синхронный переворот, разлёт по своим судьбам |
| Инстант | из руки в центр лицом вверх, держится, затем в сброс |
| Интрига | из руки в слот интриги, уменьшаясь по дороге |
| Смена карт | выбранные в угол сброса, новые из угла источника с задержкой |
| Ход бота | из мини-слота места оппонента в центр |
| Отступление в дуэли | карта атакующего в сброс, защитника обратно в руку |

### 7. Тактильность руки

`transition: transform .22s` заменяется пружинным `whileHover` (подъём, лёгкое
увеличение, свечение рамки) и `whileTap` с просадкой до 0.97. Добавляется
мягкий наклон карты к курсору в пределах ±6° на pointer-устройствах.
Неиграбельная карта не поднимается, только подсвечивается. Это устраняет
дефекты 2 и 3.

### 8. Панель действий

`ActionControls` возвращает разные деревья на каждую фазу, отсюда скачки
высоты. Дерево оборачивается в `motion.div` с `layout` и `AnimatePresence` по
ключу фазы: старое содержимое уходит вниз с затуханием, новое приходит сверху,
высота панели интерполируется. То же применяется к `.targetbar`, бейджам на
столе и пузырям речи.

### 9. Сокращение отношения к движению

`prefers-reduced-motion` через `useReducedMotion()`: перелёты становятся
мгновенной сменой позиции с кроссфейдом 120 мс, переворот — кроссфейдом вместо
3D, пружины отключаются. Hover остаётся изменением подсветки без движения.

## Что удаляется

- `apps/web/src/lib/handSlots.ts` и `handSlots.check.ts` — слоты выводятся из ID.
- `apps/web/src/lib/presence.ts` — заменяется на `AnimatePresence`.
- Полётная часть `packages/engine/src/utils/visualEffects.ts`.
  `triggerResourceFloat` остаётся: это не карты.
- Из CSS: все `fly-*` keyframes, `hand-in`, `hand-out`, `card-deal`,
  `.handcard--out`, `.minicard--out`.
- `StakedCardArena.tsx` сокращается примерно с 330 строк до 80: остаются бейджи
  и раскладка дуэли.

## Зависимости

Добавляется `motion` (бывший framer-motion) в `apps/web`. Обоснование:
`AnimatePresence` гарантирует, что карта доживает до конца своей exit-анимации,
что снимает необходимость в флагах `hasCardDeparted` и `showPile`; пружины
прерываемы по построению. Перелёт между зонами реализуется через измеренные
якоря, а не через `layoutId`, чтобы projection-трансформации motion не
конфликтовали с 3D-переворотом карты.

## Тестирование

Конвенция репозитория — файлы `*.check.ts`, запускаемые через `npx tsx`.

Зоны выводятся чистой функцией `deriveCardZones(state, viewerId)` в
`apps/web/src/lib/cardZones.ts`; `useCardZones()` — тонкая обёртка-хук над ней.
Соседний `apps/web/src/lib/cardZones.check.ts` проверяет эту функцию без DOM.
Случаи:

- две одинаковые карты в руке различаются по ID;
- карта на кону во время проверки: соседняя карта остаётся видимой (дефект 5);
- вето, положенное поверх кона;
- перенаправление;
- дуэль: обе карты в своих зонах;
- отступление в дуэли;
- смена карт;
- неизвестный ID, появившийся в руке, попадает в зону `deck`.

`packages/engine/src/resolvers/cardFlight.check.ts` переписывается: вместо
проверки «выставился ли `cardFlightEvent`» проверяется, в какой зоне оказалась
карта после разрешения действия.

Остальные check-файлы движка обновляются под `CardInstance`.

## Порядок работ

1. `CardInstance` в движке; компилятор ведёт по всем затронутым файлам.
2. `cardZones` и его check — чистая логика до всякого рендера.
3. Реестр якорей, `CardLayer`, хореограф; рука и стол переезжают на якоря.
4. Места оппонентов, слот интриги, угловые якоря.
5. Настройка пружин по каталогу движений.
6. Панель действий и остальные переходы.
7. `prefers-reduced-motion` и удаление мёртвого кода и CSS.

## Риски

Шаг 1 — механическая, но широкая правка движка: затрагивается около 23 файлов.
До завершения шага 3 игра находится в промежуточном состоянии. Работа ведётся в
ветке `feat/card-motion-system`.

Существующие паузы движка (`ACTION_HOLD_MS` равен 2200 мс) оставляют
достаточный запас для перелёта длительностью около 600 мс, поэтому темп игры не
меняется.
